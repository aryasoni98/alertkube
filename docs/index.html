Architecture

The pipeline, end to end

Every alert flows through the same six stages. No magic - just a small, inspectable Go pipeline with metrics at every hop.

Watchers
Resource-kind specialists

One watcher per kind - Pod, Node, Deployment, PVC, Job. Each owns its own reason taxonomy and emits a canonical Alert.

Store
Dedupe, mute, resolve

SHA-1 fingerprint of (kind, ns, name, reason). Mute window suppresses re-firing. Resolve TTL emits a synthetic resolution when the alert stops.

Router
Silence · inhibit · match

Time-bounded silences. Cross-kind inhibitions (e.g. NodeNotReady mutes its pods). Route rules pick the sinks per alert; default falls through.

Severity model

Three tiers. One source of truth.

Severity drives color, emoji, channel, and which sinks accept the page. PagerDuty only pages on critical; Slack takes all three on per-severity channels.

Critical
#E01E5A · :rotating_light:
  • · CrashLoopBackOff
  • · OOMKilled
  • · NodeNotReady
  • · PVC Lost
  • · Job Failed
  • · ProgressDeadlineExceeded
Warning
#ECB22E · :warning:
  • · ContainerRestart
  • · ImagePullBackOff / ErrImagePull
  • · Deployment Unavailable
  • · PVC Pending
  • · Node Cordon
Info
#4599DF · :information_source:
  • · Resolved events
  • · Operator-defined notices
  • · Low-priority signals
Watchers

Five resource kinds. One alert shape.

Pod
internal/watchers/pod.go

Restart count, container waiting reasons, OOM, image-pull. Filters by namespace and pod-name prefix (literal or regex).

CrashLoopBackOff OOMKilled ImagePullBackOff Restart
Node
watchers/node.go

Transitions only - NodeReady flip, memory/disk/PID pressure, manual cordon. Inhibits dependent pod alerts.

NotReady MemoryPressure DiskPressure Cordon
Deployment
watchers/deployment.go

Unavailable replicas and ProgressDeadlineExceeded. Details payload carries desired/ready/updated counts.

Unavailable ProgressDeadline
PersistentVolumeClaim
watchers/pvc.go

ClaimLost is critical. ClaimPending fires as warning so storage flapping doesn't page on-call.

Lost Pending
Job
watchers/job.go

Backoff-limit hit. Details include active/succeeded/failed counts + the condition message.

JobFailed

Pipeline

From raw event to a page worth taking

1
Fingerprint

sha1(kind|ns|name|reason) truncated to 12 chars. Same fingerprint = same alert = dedupe.

2
Mute window

muteSeconds blocks re-firing of the same fingerprint. Last-sent table self-cleans after an hour.

3
Silence

Matchers + an RFC3339 until. Annotation alert-silence-until works per-resource.

4
Inhibit

A source alert arms a window; matching target alerts are dropped while the window holds. Configurable equal keys.

5
Route

First matching routing.match wins. No match falls through to default sinks.

6
Resolve

Background sweeper expires alerts past their TTL and emits a synthetic resolved event downstream.

Sinks

Five sinks. One interface.

Every sink implements Name / Send / Supports. Add a new one in ~30 lines; register it at boot.

PagerDuty critical only Events API v2 Trigger / Resolve with dedupKey = fingerprint PAGERDUTY_ROUTING_KEY

Config

YAML first. Env as fallback.

One config.yaml drives routing, inhibitions, silences, filters, mute/resolve windows, and per-severity channels.

  • · routing - match labels → sinks
  • · inhibitions - source → target with equal-keys window
  • · silences - matchers + RFC3339 until
  • · filters - comma/regex namespace + pod-name lists
config.yaml YAML 
cluster: prod-eu-west-1
metricsAddr: ":9090"

behavior:
  muteSeconds: 600
  ignoreRestartCount: 30
  resolveTTLSeconds: 600

channels:
  critical: alerts-critical
  warning:  alerts-warning
  info:     alerts-info

routing:
  - match: {severity: critical}
    sinks: [slack, pagerduty]
  - match: {severity: warning}
    sinks: [slack]
  - match: {kind: Job}
    sinks: [slack, webhook]

inhibitions:
  - source: {kind: Node, reason: NodeNotReady}
    target: {kind: Pod}
    equal:  [node]
    duration: 10m

silences:
  - matchers: {namespace: staging, severity: warning}
    until: 2026-06-30T00:00:00Z
Observability

Every emitted alert.

Send latency per sink.

For liveness + readiness.

Install

Ship it in three commands

helm
helm upgrade --install alertkube ./helm \
  --namespace monitoring --create-namespace \
  --set cluster=prod-eu-west-1 \
  --set slack.webhookUrl=$SLACK_WEBHOOK_URL \
  --set pagerduty.routingKey=$PD_ROUTING_KEY
docker
docker run --rm \
  -e SLACK_WEBHOOK_URL=$SLACK_WEBHOOK_URL \
  -e CLUSTER_NAME=local-dev \
  -v $HOME/.kube/config:/root/.kube/config \
  alertkube:0.0.1
